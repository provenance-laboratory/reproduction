# Finding, 5 September 2026 — the tree does not satisfy its own commitment check

⛔ **`check_commitments.py` refuses on a clean checkout at HEAD.** Three consecutive runs, identical
output, working tree byte-identical to `6563954`:

```
⛔ the anchor file is not exactly what the proofs require: 2 block(s) are pinned that
   NO PROOF NAMES: [964878, 964881]. A pin nobody needs is a root somebody added.
```

`PUBLICATION-CHECKLIST.md` §2 opens with that command and says what a failure means: *"If not, the
pre-registration is VOID and nothing below is worth doing."* **So the package cannot be published
today**, and that — not measurement 4, and not measurement 6 — is what currently stands between
this work and its reproduction window.

---

## 1. ⛔ The two rules cannot both be satisfied

Both are in force, both were right when written, and they now contradict each other.

**`PRE-REGISTRATION-v11-CONFIRMATORY.md` §2d — ANCHOR FACTS, monotonic** *(lines 80–98, and the
same list in v10)*:

> Each line is a Bitcoin block height and the merkle root `ANCHORS.json` records for it. **Every
> line must remain present and unchanged; new heights may be added and are not a violation.**

```
964878     b9fef3d8dd2fc6b2945cb580525f25beaf5612b7b71e3a1b78799e22f353dce0
964881     45cb82a2d9677e318826afb6fd6f3a6be84b5cf94780ee1487b49097d5293579
```

**`check_commitments.py` lines 355–360 — the pinned set must EQUAL the named set**:

```python
extra = sorted(pinned - named)
if extra:
    return False, ("%d block(s) are pinned that NO PROOF NAMES: %s. A pin nobody needs is a "
                   "root somebody added." % (len(extra), extra[:4]))
```

⇒ **§2d requires those two heights to stay. The gate refuses because they are there and no current
proof names them.** No edit to `ANCHORS.json` can satisfy both: removing the lines violates the
monotonic rule in an anchored document; keeping them fails the gate.

⚠️ **The monotonic rule exists for a good reason and should not simply be dropped.** v11 §2d records
it: *"v10's own anchoring added two heights to this file and broke nothing — which is the property
the byte pin could never have, and the reason this section exists."* The equality check exists for
a good reason too: an unexplained pin is a root somebody added. **The defect is that neither was
written knowing the other would outlive a superseded proof.**

## 2. ⚠️ How it became visible today, and what that says about the projection

The same command returned **exit 0** earlier the same day, on the same commit. Between the two runs
the only thing that changed outside version control was `package/`, which `build_package.py`
regenerated — **step 1 of `MEASUREMENT-4-RUNBOOK.md`, a routine and correct action.**

`pin_anchors.heights()` builds its document set like this:

```python
for _o in sorted(HERE.rglob("*.ots")):
    if ".superseded-" in _o.name:
        continue
    _d = _o.with_suffix("")
    if _d.exists() and _d not in docs:
        docs.append(_d)
```

`HERE.rglob` is **recursive over the whole directory, including `package/`** — which is generated,
git-ignored, and holds twelve `.ots` files. So the set of proofs the anchor check consults depends
on the contents of a build output.

⛔ **A build artifact is an input to the protocol's own gate.** Whatever the two heights' exact
provenance, that is the defect: rebuilding a regenerable directory changed the verdict of the check
that decides whether the pre-registration is void.

⚠️ **The old `package/` bytes are gone** — it is git-ignored, so there is no copy to compare
against, and the precise mechanism by which it supplied those two heights cannot now be
demonstrated. *That inability is itself part of the finding:* a directory that can change a gate's
verdict was not under version control.

⇒ The projection should be over the proofs this artifact **requires**, resolved from the protocol
documents and `anchor_status.ALWAYS`, and must exclude generated output. The comment above that
loop already says the projection exists so that *"a proof this project treats as required cannot
fall outside the pin set"* — the loop widened the set in the other direction as well, and nothing
noticed.

## 3. ⛔ Separately: the package ships the answer

`build_package.py` writes `NO-TARGET.md`, which states:

> A digest published before the commitment is a target reproducers self-select against… **An
> earlier version of this package shipped the digest anyway, which defeated the ordering the
> protocol was rewritten to establish.**

It still does. The reference weights digest `a4afb5c86dd88ae5…` is present in three shipped
protocol documents:

```
package/PRE-REGISTRATION-v5-CONFIRMATORY.md   quotes it to show a pipeline edit was numerically inert
package/PRE-REGISTRATION-v8-CONFIRMATORY.md   quotes it to show a provenance change altered no result
package/PRE-REGISTRATION-v9-CONFIRMATORY.md   same sentence as v8
```

All three are correct, signed and anchored, and all three were added to the package **after** v3
made it target-free. Each was added by asking *"is this part of the protocol chain?"* and never
*"does this contain the answer?"*

⇒ The target-free rule guards **one file** — `EXPECTED.json`, where the target was the day the rule
was written — and never projects over the assembled package. `NO-TARGET.md` is a **note inside a
file, not a control**, and it was untrue for as long as it existed.

⚠️ **And it is worse than a packaging bug: the documents are public.** They are committed and
pushed, so the digest has been readable in the repository since v5 was published. The ordering v3
§3 establishes — commitment first, target after — is **already defeated for anyone who reads the
repository**, and no change to the package restores it. The documents are signed and anchored and
cannot be edited.

**This can be disclosed. It cannot be undone.** Any reproduction filed after v5 was published could
in principle have self-selected against a known target, and the paper must say so when it reports
what the window produced.

## 4. What has to happen, in order

1. **Decide the anchor contradiction.** It needs a v12: either §2d's monotonic rule gains an
   explicit exception for heights whose proof has been superseded, or the equality check becomes a
   containment check with the superseded heights carried as declared history. Both are amendments;
   neither is an edit to an anchored file.
2. **Move the target-free rule from one filename to a projection over the package.** A prepared
   patch is held outside this tree (it scans every shipped byte for the reference digest and fails
   closed) and is **deliberately not applied** — `build_package.py` is pinned by v11 §2b at
   `7087ec4aeaf6b0bc`, so applying it is part of the same v12, not a change to make first.
3. **Take `pin_anchors.heights()` off `rglob`** so a generated directory cannot feed the gate.
4. **Then** publish the commitment and fix the window's close date.

⚠️ **Nothing above is a reason to weaken a rule so the tree passes.** The gate is refusing on a real
condition. The amendment records what the condition is and why the resolution is legitimate — which
is the same standard every earlier version of this protocol was held to.
